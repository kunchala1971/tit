JSP Architecture, Setup & Life Cycle Guide

Learn JavaServer Pages (JSP) from scratch: setup JDK and Tomcat Server in VS Code, master JSP vs Servlets differences, and understand the 5-phase JSP execution lifecycle.

By KSR 10 min read Updated September 2026

JSP (JavaServer Pages) is a powerful server-side technology used to create dynamic, data-driven web pages in Java enterprise applications. By combining static template text (HTML, XML, CSS) with dynamic JSP elements, developers can separate user interface presentation from backend business logic cleanly.

1. Prerequisites & Development Environment Setup

Before creating JSP web applications, ensure your development environment is properly configured with JDK, a web container (Apache Tomcat), and a modern code editor.

Required Environment & Plugins
  • JDK (Java Development Kit): Ensure JDK 11+ or JDK 17+ is installed and JAVA_HOME environment variable is set.
  • Apache Tomcat Server: Download and install Apache Tomcat (v9.0 or v10.0+).
  • IDE (VS Code / Eclipse): For VS Code development, install the following essential extensions:
    • Extension Pack for Java (Microsoft)
    • Community Server Connectors
    • Apache Tomcat Extension
    • JSP Language Support
    • Debugger for Java

2. What is JSP & Template vs Elements

JSP is composed of two primary parts:

  • Template Text: Static content like standard HTML, XHTML, XML, or plain text formatting that describes page structure.
  • JSP Elements: Dynamic server-side tags including Scriptlets, Directives, Action tags, Custom tags, and JSTL tags that generate dynamic content at runtime.
<!-- Example of Template Text (HTML) mixed with JSP Elements -->
<!DOCTYPE html>
<html>
<head><title>My First JSP Page</title></head>
<body>
  <h1>Welcome to Telugu IT Tutorials</h1>
  <%-- JSP Scriptlet Tag --%>
  <%
    out.println("JSP is better than Servlets for UI generation!");
  %>
</body>
</html>

3. Key Advantages of JSP over Servlets

While both Java Servlets and JSP execute on the web server to produce dynamic web content, JSP offers significant developer productivity and maintenance benefits:

Feature Java Servlets JavaServer Pages (JSP)
Ease of Development Requires writing HTML inside Java string statements (out.println("<html>")), making UI creation cumbersome. Designed HTML-first. Java code is embedded into standard HTML tags, making UI design intuitive.
Recompilation Manual source re-compilation is required every time Java servlet code changes. Automatic re-compilation by the web container whenever the .jsp file is edited and saved.
Configuration & Access Must be registered and mapped inside web.xml or annotated with @WebServlet. Cannot be accessed directly. Can be requested directly by URL path just like static HTML pages (e.g., http://localhost:8080/app/index.jsp).
Architecture Presentation logic and business logic are tightly coupled in Java code. Promotes MVC architecture: clean separation of presentation UI logic from backend business logic.

4. Internal Working & Execution Flow of JSP

When a web browser requests a .jsp file from Apache Tomcat, the container follows a multi-step execution pipeline:

  1. Client HTTP Request: The web client (browser) sends an HTTP request for a JSP page to the web server.
  2. Container Location: Upon receiving the request, the JSP Container (Tomcat) searches for and reads the target JSP file.
  3. Translation Phase: The container translates the JSP page into equivalent Java Servlet source code (.java). Static template text is converted into out.println() statements, while JSP elements become Java code.
  4. Compilation Phase: The JSP Container compiles the generated Servlet .java file into bytecode (.class file).
  5. Request Processing & Response: The container instantiates the Servlet class, invokes the service method, executes the business logic, and streams the HTML response back to the client.

5. The 5 Life Cycle Phases of JSP

Every JSP page managed by a web container transitions through 5 distinct lifecycle stages:

Phase 1
1. Page Translation

The web container translates the .jsp file into its underlying Java Servlet source file (e.g., index_jsp.java).

Phase 2
2. Compilation

The Java compiler compiles the generated servlet source code into executable bytecode (.class file).

Phase 3
3. Loading & Init

The container loads the compiled .class into memory, instantiates the servlet, and invokes jspInit().

Phase 4
4. Request Handling

For every client HTTP request, the container invokes _jspService() concurrently to generate output response.

Phase 5
5. Destroy

When server shuts down or app unloads, jspDestroy() is called to clean up open resources and destroy object.
