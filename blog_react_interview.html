Top 10 React Interview Questions Every Developer Should Know

Master these essential React concepts before your next frontend technical interview.

React is currently the most popular frontend library in the world. Whether you are a fresher looking for your first job or an experienced developer switching stacks, you are guaranteed to face React questions in modern frontend interviews. Below, we break down the most critical concepts you must understand, complete with examples and "Pro Tips" to help you stand out.

1 What is the Virtual DOM and how does it work?

The Virtual DOM (VDOM) is an in-memory representation of the Real DOM. Manipulating the Real DOM is extremely slow and expensive. When a component's state changes, React updates the Virtual DOM first.

It then compares the updated Virtual DOM with a snapshot of the previous Virtual DOM (a process called Diffing). Once it identifies exactly what changed, it updates only those specific nodes in the Real DOM (a process called Reconciliation).

Pro Tip: Don't just say "it makes React fast." Explain the Diffing algorithm (which operates in O(n) time) and mention Reconciliation.
2 Explain the difference between functional and class components.

Historically, Class components were required if you needed to manage state or use lifecycle methods (like componentDidMount). Functional components were simply "dumb" components that accepted props and returned JSX.

With the introduction of React Hooks in version 16.8, functional components can now manage state and side effects. Today, functional components are the industry standard because they are less verbose, easier to test, and avoid the confusing behavior of the this keyword in JavaScript classes.

3 What are React Hooks? Name the most important ones.

Hooks are special functions that allow you to "hook into" React state and lifecycle mechanics directly from functional components without writing ES6 classes.

  • useState: Adds local reactive state to components with functional updater capabilities.
  • useEffect: Handles asynchronous side effects (HTTP fetch requests, DOM listeners, timers, subscriptions) and provides cleanup functions to avoid memory leaks.
  • useContext: Subscribes cleanly to React Context providers without consumer render props nesting.
  • useReducer: Manages complex state transitions with an action-dispatch pattern, mirroring Redux logic locally.
  • useRef: Holds a mutable reference that persists across re-renders without triggering a re-render when mutated.
  • useMemo & useCallback: Memoizes expensive calculation results and function references respectively.
// Example: Counter Hook with functional update to avoid race conditions const [count, setCount] = useState(0); const increment = () => setCount(prev => prev + 1);
4 What is "Prop Drilling" and what are the best ways to solve it?

Prop Drilling occurs when you pass data through multiple intermediate child components that do not actually need that data, solely to deliver it to a deeply nested descendant component. It creates tight coupling, makes refactoring tedious, and clutters component interfaces.

Solutions include:

  • React Context API: Built-in mechanism for low-to-medium frequency global data like Theme, User Authentication, or Language settings.
  • Component Composition: Passing components as `children` or render props so intermediate components don't even need to be aware of the props.
  • Modern State Libraries (Zustand / Redux Toolkit): For high-frequency enterprise state with selective subscriptions that prevent unnecessary child re-renders.
Architect Pro Tip: In enterprise apps, don't use Context API for rapidly changing values (like continuous scroll position or real-time trading feeds) because every consumer component re-renders when the context value changes. Use Zustand with selectors instead.
5 What are the strict Rules of React Hooks and why do they exist?

React enforces two fundamental rules for all hooks (both native and custom):

  1. Only Call Hooks at the Top Level: Never call Hooks inside loops, conditions, or nested functions.
  2. Only Call Hooks from React Functions: Call them from React functional components or custom hooks, never from regular vanilla JavaScript functions.

Why? React relies on the call order of hooks during each render pass. Internally, React tracks component hook values in a single ordered linked list. If a hook is placed inside an if block that evaluates to false on the next render, the hook execution order shifts, causing every subsequent hook to read data belonging to a completely different hook!

6 What is the difference between `useMemo` and `useCallback`? When should you NOT use them?

Both hooks prevent unnecessary recalculations or re-renders across render passes, but they serve different purposes:

  • useMemo: Caches the result of a calculation. Syntax: const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
  • useCallback: Caches the function definition itself across re-renders to maintain referential equality. Syntax: const memoizedFn = useCallback(() => doSomething(a), [a]);
When NOT to use them: Premature optimization is harmful. Both hooks incur memory overhead and dependency array comparison costs. For simple calculations (like filtering a 20-item list or basic math), the overhead of useMemo is actually greater than simply recomputing on every render!
7 Why are `key` props required in lists, and why is using `array index` an anti-pattern?

Keys help React identify which items in a list have been added, removed, or reordered during reconciliation. React compares the keys between the old and new Virtual DOM to determine whether to reuse an existing DOM node or destroy and re-create it.

Why Array Index as Key is Dangerous: If a list item is prepended, removed, or sorted, every item's array index changes! React thinks the first item was modified rather than a new one inserted, causing UI bugs with controlled form inputs, unexpected animation glitches, and severe performance degradation. Always use stable, unique IDs (e.g., database primary key item.id).

8 Controlled vs Uncontrolled Components: What are they and when to use each?

In a Controlled Component, form element values (<input>, <textarea>, <select>) are handled directly by React state via value and onChange. React is the "single source of truth."

In an Uncontrolled Component, form data is handled by the browser's DOM directly. You retrieve values on submission using a useRef() hook.

  • Choose Controlled: When you need instant real-time field validation, conditional disabling of submit buttons, or dynamic input formatting (e.g., credit card masking).
  • Choose Uncontrolled: When handling file uploads (<input type="file"> is always uncontrolled in React) or optimizing massive forms with hundreds of input fields where per-keystroke re-renders harm performance.
9 What are React Server Components (RSC) and React 19 Innovations?

React Server Components (RSC) execute exclusively on the web server before any HTML or JavaScript is streamed to the client browser.

  • Zero Client Bundle Size: Heavy server-side npm packages (e.g., markdown parsers, syntax highlighters) stay on the server and do not bloat the user's JavaScript download.
  • Direct Backend Access: Server components can query the database directly or read local file systems securely without building separate REST API endpoints.
  • React 19 Actions: Introduces useActionState, useFormStatus, useOptimistic, and the new use() API to read Promises and Context dynamically during render.
10 How do you systematically optimize performance in a massive React application?

Senior technical interviewers frequently probe candidate readiness with this real-world question. An ideal answer covers:

  1. Code Splitting with React.lazy & Suspense: Break monolithic JavaScript bundles into dynamic route-level chunks so users only download the code for the page they are viewing.
  2. Component Memoization: Wrap pure visual components in React.memo to skip rendering if props have not changed.
  3. Windowing & Virtualization: When rendering large tables or lists (1,000+ items), use libraries like react-window or tanstack/react-virtual to only render visible DOM rows in the user's viewport.
  4. State Colocation: Keep state as close as possible to where it is used. Pushing local state up to global stores causes entire trees to re-render unnecessarily.
